# Что делать, если отчёт не обновился

Запуск пайплайна заканчивается одним из четырёх кодов. Ниже — что каждый значит и что делать. Подключение к базе: `psql -h localhost -p 5435 -U dq dq`.

## Где смотреть

Последние запуски:

```sql
select load_id, report_date, status, message, started_at
from meta.load_runs order by load_id desc limit 5;
```

Что не прошло в конкретном запуске:

```sql
select check_code, level, status, violations, details
from meta.check_results
where load_id = 123 and status <> 'passed'
order by check_code;
```

Примеры нарушающих строк лежат в колонке sample той же таблицы, до 20 штук.

## Код 0 — опубликовано

Витрина обновлена. Предупреждения разбираются в рабочем порядке: данные в витрине уже есть.

| Предупреждение | Что проверить |
|---|---|
| W01 дубли | Источник отдаёт заказы повторно. Витрина верная, но стоит сообщить владельцам API |
| W02 пустой город | Часть заказов попадёт в «не указан». Если доля растёт — выяснить, что поменялось в приложении |
| W03 новый город или способ оплаты | Добавить значение в справочник или выяснить, откуда оно взялось |
| W04 поздние заказы | Прошлые дни пересобраны, цифры за них изменились. Предупредить тех, кто уже смотрел отчёт |
| W05 мало заказов | Самое важное предупреждение. Источник может сам терять данные и при этом сходиться со своим контрольным итогом. Сверить с другим источником, например с платежами |
| W06 дорогие заказы | Посмотреть пару примеров из sample: настоящие это заказы или ошибка в сумме |

## Код 1 — заблокировано проверкой

Витрина не обновлялась, руководитель видит последнюю корректную версию. Кандидат лежит в staging.orders_candidate, сырые ответы — в raw.

| Проверка | Вероятная причина | Что делать |
|---|---|---|
| B01 | Источник изменил формат: поле пропало или переименовано | Связаться с владельцами API. Если изменение навсегда — поменять контракт и код |
| B02, B04–B07 | Испорченные значения в источнике | Посмотреть sample, отправить примеры владельцам API |
| B03 | Две разные версии заказа с одним временем изменения | Источник противоречит сам себе, нужен разбор с владельцами API |
| B08 | Пришло не всё: пустая страница, оборванная выгрузка | Обычно достаточно перезапуска |
| B09, B10, B11 | Нет данных за день или их слишком мало | Проверить, работает ли источник за этот день |
| B12 | Витрина разошлась со staging | Ошибка в коде сборки витрины, а не в данных |

## Код 2 — источник недоступен

API не ответил после трёх повторов. Ничего не изменилось. Перезапустить, когда источник поднимется.

## Код 3 — ошибка пайплайна

Сломался сам пайплайн, а не данные. Текст ошибки — в message. Исправить и перезапустить.

## Восстановление

После устранения причины достаточно перезапустить последний день:

```
.venv/bin/python -m dqpipe.run --date 2026-09-30
```

Окно загрузки — 7 дней, поэтому все затронутые дни перезаберутся. Повторный запуск безопасен: данные за дни окна заменяются, а не дописываются.

## Монитор свежести

```
make freshness TODAY=2026-10-01
```

Код 1 означает одно из двух: последний опубликованный день не вчерашний, или какой-то запуск висит в running дольше часа. Монитор стоит запускать по расписанию утром. При недоступном источнике пайплайн ничего не публикует, и без монитора это заметит только руководитель.
